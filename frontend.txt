Baseball-TMS será una plataforma web para la gestión de torneos de béisbol bajo los 
siguientes criterios:

Frontend: El frontend será desarrollado utilizando HTML, CSS y JavaScript puros, para no depender de frameworks que puedan 
romperse con cada actualización o cambio en sus versiones. El sitio no se creará como una Single Page Application, sino como una aplicación multipágina.
La interfaz se requiere que sea intuitiva, responsiva y 
fácil de usar para mejorar la experiencia del usuario, ya que parte de los usuarios finales pueden no estar 
familiarizados con tecnologías avanzadas, y tendrá un estilo deportivo profesional. Se requieren los media queries más adecuados 
para que la interfaz se adapte a celulares, tabletas, laptops y pantallas de escritorio. Se utilizará JWT (JSON Web Tokens) para 
garantizar la seguridad y autenticación de los usuarios, siempre con el enfoque necesario para adaptarse a los roles de cada 
usuario. Los roles de usuario definidos en el backend (API/v1/) son:
- Administrador
- Manager/Entrenador
- Jugador

Detalles de diseño (Interfaz intuitiva, minimalista, con toque deportivo y acceso rápido a información relevante):
- El API que se consumirá se encuentra localizado en /API/v1/ (El que ya fue creado anteriormente).
- En la raíz del proyecto se creará la estructura de folders del frontend (scripts, styles, assets, etc.)
- El logo de plataforma es /assets/logo/sindicato.jpg
Utilizar los colores del logo proporcionado para darle el estilo a la interfaz de usuario.

Comenzaremos por partes, así que este sólo es el prompt inicial y lo que se requiere es definir la estructura básica del proyecto y los componentes principales.
La primera página que será creada será el dashboard principal (bajo nombre index.php en la raíz del proyecto), habiendo 2 casos distintos:
1) Si no se ha hecho login, sólo se mostrará el calendario de juegos (Comenzando con el más reciente), y en alguna parte de la pantalla se mostrará el enlace, botón o cualquier elemento para hacer login.
2) Si ya se hizo login, se mostrará el mismo calendario de juegos, se mostrará el usuario loggeado y nombre del equipo al que pertenece, y se mostrará cualquiera de los siguientes 3 casos:
    A) Si es un usuario de tipo jugador, tendrá acceso a sus datos ya sea dando click en su nombre de usuario, o desplegando un popup menu al hacer click en el nombre de usuario y apareciendo la opción "Mi perfil", llevándote a /user/profile.php, por medio de un formulario pero sin opción de modificar nada (sólo lectura).
    B) Si es un usuario de tipo manager/entrenador, tendrá acceso a los datos del equipo al que pertenece por medio de click en el nombre del equipo y un popup menu que de la opción de "Mi equipo", llevándote a /team/manage.php,  a todos los jugadores que conforman el equipo en forma de lista con la opción de ver sus detalles personales (user/profile.php), por medio de un formulario pero sin opción de modificar nada (sólo lectura).
    C) Si es un usuario de tipo admin, tendrá acceso a un menú especial "Catálogos" que desplegará un submenú con los siguientes elementos (Categorías, Equipos, Usuarios, Campos, Juegos), cada uno te llevará al CRUD correspondiente, por ejemplo, Categorías a /catalogs/categories/crud.php, Equipos a /catalogs/teams/crud.php, Usuarios a /catalogs/users/crud.php, y así sucesivamente.
    NOTA: Los catálogos aún no se deben implementar, sólo dejar listo el menú y el submenú apuntando a sus respectivas rutas. Primero quiero que te enfoques en la creación del dashboard principal y su funcionalidad básica, así como el formulario de login. Asegúrate de que el diseño sea responsivo y compatible con diferentes dispositivos.

NOTA: Todo código será desarrollado SIEMPRE EN INGLÉS utilizando estándares en nomenclatura y comentando el código en la 
medida de lo posible. El texto en la interfaz por el contrario, será en español.
